# Аудит ffl-go 0.3.0: итог

## Что проверялось

Модуль `github.com/Ruddy35/ffl-go` на коммите **51c2312**: переход на библиотеки Figram v0.3.0 и
протокол 3 (`Bot.Outcome`, `Snapshot.Pending`, `Action.Outcomes`/`Token`/`Detached`,
`CodeSnapshotTooLarge`, валидатор ответов `checkReply`, документация и тесты). Спецификация —

`docs/host-contract.md` (разделы 1–6), `docs/embedding.md` («Go»). Эталонные валидаторы —
`clients/python/protocol.py` и `clients/go/main.go` репозитория Figram. Бриф — `tools/BRIEF7.md`.

Один агент (`fflgo`), рабочее дерево `audit7/fflgo` на 51c2312; код модуля агент не менял (свои
программы и копии модуля с дефектами — в `agents/fflgo/`). Каждая проверка показана красной на
намеренном дефекте и зелёной на настоящем коде.

## Находки и их судьба

| Уровень | Находка | Судьба |

| **P0** | Запросы кодировались `json.Marshal`: `&`, `<`, `>` превращались в 6-байтовые escape-последовательности. Движок держит новый снимок в пределах 15/16 лимита в своей кодировке, а ffl-go отправлял его обратно длиннее. С действием `<ping>&co` у снимка у лимита шаг давал `too_large` вместо `snapshot_too_large`, после чего `Outcome` и `Restart` с сохранённым снимком тоже падали с `too_large`: пользователь застревал. | **исправлено** в 361815c: запросы кодируются как у движка (без HTML-экранирования, U+2028/U+2029 сырыми байтами); тесты `TestSnapshotTooLargeEscapedNames`, `TestEncodeLine` |
| P1 | Карты `Resume` и `Timers` теряют порядок ключей движка; при `Restart` и восстановлении `cancel_timer` идут в другом порядке | **описано** (README, CHANGELOG 0.3.0 Known issues): для планировщика по разделу 3 контракта хоста порядок отмен не важен; побайтовое воспроизведение — через сырые строки `Bot.Request` |

## Остаточные риски

- Порядок ключей `Resume`/`Timers` (P1 выше) остаётся: исправление требует сменить тип
  `Snapshot` (сырой JSON или упорядоченные карты), это изменение API для следующей версии.
- Пробелы эталонных валидаторов Figram (не ffl-go), найденные дифференциальным сравнением:
  Go-эталон `clients/go` принимает любой текст после ответа и ответ `result` на `hello`;
  Python-эталон принимает `-0` как число и отвергает пустой текст ошибки. Движок таких ответов
  не пишет; это кандидаты для 0.3.1 Figram.
- Замечено при архивации (P3, TEST_MATRIX.md): после исправления P3-1 `decodeJSON` принимает
  после ответа не только пробельные символы JSON, но и `\v`, `\f`, U+0085, U+00A0 (проба — код
  0). Следствия нет (ответ пишет библиотека в том же процессе); исправление в одну строку — для
  ffl-go 0.3.1.
- Мутанты агента на исправленном коде: 16 из 18 убиты (2 переписаны под новый код), 2 выжившие
  практически эквивалентны (TEST_MATRIX.md).
- Аудит не обещает найти все ошибки: проверено то, что перечислено в TEST_MATRIX.md и в отчёте
  агента, с журналами настоящих запусков.
