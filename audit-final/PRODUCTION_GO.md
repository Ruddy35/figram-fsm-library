# Production-like хост на Go (встроенный движок: cgo + настоящий `libfigram.a`)

Полный отчёт: `agents/host-go/REPORT.md`. Код: ветка `audit/host-go`, каталог `audit/host-go/` (коммиты 567e9e0,
4c098d2, f57f923, a5c061b). Движок: `libfigram.a` свежей сборки baseline (Lean 4.35.0 из исходников, gcc/libstdc++),
sha256 `eaae0e08…`; в бинарнике хоста 1516 символов `Figram` — ни мока, ни процесса `figram-engine` в пути нет.
Go 1.24.7, SQLite — modernc.org/sqlite v1.34.5. Выходы: `hosts/out/go/`.

## Собственный биндинг cgo (решения о владении и потоках)
* `Init()` = `sync.Once` (исходный `figram_init` не потокобезопасен — P-08); `sigaltstack` вызывающего потока
  сохраняется и восстанавливается вокруг `figram_init` (рантайм Lean его подменяет — P-22).
* Семафор одновременных вызовов C (по умолчанию GOMAXPROCS) — ограничивает число потоков ОС, «запертых» в C.
* Строки: сырой NUL отвергается (`ErrNUL`, иначе C обрезал бы запрос); вход копируется в malloc, ответ — в память Go
  и всегда освобождается `figram_free`.
* `*Machine` владеет одной ссылкой; `Request` берёт in-flight-ссылку; `Close` запрещает новые вызовы, ждёт выхода
  текущих из C и вызывает `figram_unload` ровно один раз. Без счётчика in-flight — use-after-free (красные контроли
  `TestUnsafeUnloadIsRed`, вариант `unload-no-wait` — SIGSEGV в cgo).
* Причина отказа загрузки — через `figram_check_json` (NP-06).

## Хост
Те же правила, что у Python-хоста (общий `domain.md`: G1, G2, `hw_seq` + `restart`, `outbox.key UNIQUE`, валидация
входа), но свой код; HTTP через unix-сокет (`/update` → 200/503 как webhook Telegram), мьютекс писателя SQLite,
строгая проверка каждого ответа движка, отображение сбоев движка на FFI (`kill` хоста внутри вызова, `hang` до входа в
C, порча/обрезка/мусор/подмена id/плохой снимок/неизвестное действие), перезагрузка документа под нагрузкой
(новый автомат загружается до изменений, старый выгружается после выхода своих вызовов).

## Результаты
* **15/15 корпусов PASS**, 23 инварианта на сценарий (26 на adversarial).
* **RED-матрица:** 25 прогонов, каждый из 26 инвариантов хотя бы раз красный; контрольные прогоны исправного хоста — PASS.
* **Go против Python** (нормализация N1–N6 задана до сравнения): 13 сценариев совпали полностью (все пользователи,
  переходы, итоговые снимки, множества эффектов); booking-1/2 — расходятся только победители гонки за слот, агрегаты
  (итоговые состояния, брони по слотам, 96 переходов, эффекты по видам) равны. **Необъяснённых различий 0.** Значит,
  встроенный движок (gcc-сборка) и процесс `bin/figram-engine` (официальная сборка) дали одинаковые переходы на
  ≈10 000 обновлений, включая восстановление, ремонт, обновление документа и устаревшие жетоны. Красный контроль
  сравнения (подмена трёх выходов) — DIFF, код 1.
* **`go test -race`** (биндинг + хост, 16 тестов) — PASS; контроль детектора — FAIL с DATA RACE, как и должно.
* **Soak 11 мин:** 298 035 обновлений (451/с), 132 перезагрузки документа, 0 ошибок; потоки 12,8→13,0, fd 56,5→57,1,
  горутины 31,9→31,5, VSZ ×1,004; RSS ×1,146 при росте БД до 151 МБ — приписано кэшу страниц SQLite (HYPOTHESIS):
  5000 циклов загрузки/выгрузки движка без БД (2 млн вызовов) роста RSS не дают; 20 000 потоков ОС, умирающих после
  вызова, — без роста.
* **Оверхед:** переход cgo 75 нс; `step` 19,9 мкс последовательно, 14,8 мкс/оп на 4 горутинах; загрузка+выгрузка pizza
  0,43 мс; движок ≈5 % стенного времени процесса под нагрузкой.

## Находки через этот хост (новые для встроенного пути)
NP-01 = P-09 (SIGABRT хоста при `RLIMIT_AS` ≤ 3 ГБ), NP-02 = P-22 (поток libuv + io_uring SQPOLL, +2,2 ГБ VSZ, подмена
`sigaltstack` у M рантайма Go, нет `figram_shutdown`), NP-03 (C-строки без длины, U+FFFD, разное поведение на пустой
строке у FFI и процесса), NP-04 = P-08 (гонка init: 235 из 300 с 8 потоками), NP-05 (после обновления документа в
`snapshot.timers` остаются имена старого — строгий валидатор хоста зацикливается; следствие P-04), NP-06 (нет причины
отказа загрузки). Известные ET-01/02/03/07, HP-01, PH-02…08, FC-03 подтверждены ссылками.

## Не проверено
Настоящее зависание внутри C (вызов cgo не прервать — защита только сторожевым перезапуском процесса); TSan/ASan
процесса Go вместе с библиотекой; хост из нескольких процессов на одной БД; потеря питания; профиль SQLite.
Независимость от Python-хоста частичная: неоднозначности `domain.md` согласованы чтением его кода (движок и транспорт
при этом разные — это и есть проверяемое).
