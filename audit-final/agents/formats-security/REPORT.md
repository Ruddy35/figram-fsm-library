# formats-security — предварительные результаты (работа прервана)

Отчёт составлен оркестратором по двум сообщениям-передачам агента и его журналу: сам агент `REPORT.md` не
написал. Работа агента была **дважды остановлена классификатором безопасности среды** — при написании генератора
враждебных входов и при обработке результатов замеров исчерпания ресурсов. После второй остановки направление
закрыто и другим агентам не передавалось. Корректностные задачи (roundtrip, таблица RFC, схема ↔ декодер, таблица
запросов) выполнил отдельный агент formats-correctness (`agents/formats-correctness/REPORT.md`).

Бинарники: `bin/figram`, `bin/figram-engine` архива (метка PREBUILT в журнале; позже признаны равными официальной
свежей сборке — CI run 39330382243). Ограничения: `nice` + `timeout` + `prlimit --as=4 ГБ`. Журнал:
`LOGS/bench_prebuilt.log` (код 0, 27 строк), данные — `LOGS/bench_prebuilt.json`. Скрипты (`lib.py`, `oracle.py`,
`bench_scaling.py`) остались незакоммиченными в рабочем дереве агента и в ветку не попали.

Отрицательные наблюдения: массивы из 1 млн скаляров и 1 млн объектов разбираются ≈1 с без переполнения стека;
глубина 256 проходит со стеком 64 КБ; список `do`/`requires` из 1 млн элементов декодируется со стеком 256 КБ.

## Находки (предварительные; сведены в ISSUES_PRODUCT.md как P-10, P-16, P-18, P-19, P-24)

| ID | класс | P (предложено) | уверенность | суть |
|---|---|---|---|---|
| FS-1 | PRODUCT | P2 | LIKELY → подтверждено другими (ET-08, X1, C4) | проверка дублей ключей `acc.any` в `parseObj` — O(N²) |
| FS-2 | PRODUCT | P2 | LIKELY → подтверждено (ET-08) | накопление числа по цифрам — O(n²) (эхо `id`, `token`, `seq`) |
| FS-3 | PRODUCT | P2 | CONFIRMED на bin | ≈50 × память на байт строки; 50 МБ → OOM-паника процесса движка; во встроенном варианте — хоста (HYPOTHESIS, позже подтверждено FFI-13 для Go) |
| FS-4 | PRODUCT/DOC | P2 | HYPOTHESIS → подтверждено (PC-10, CV-C5) | ошибка разбора текста → `id:null`; клиент Python убивает общий процесс |
| FS-5 | PRODUCT | P3 | HYPOTHESIS → подтверждено (FC-03) | невалидный UTF-8 в потоке → U+FFFD; файлы — строго |
| FS-6 | PRODUCT | P3 | HYPOTHESIS → подтверждено (FC-06, CV-C8) | диагностика печатает имена без экранирования |
| FS-7 | PRODUCT | P3 | HYPOTHESIS → подтверждено (ET-12, X2) | `token` не ограничен 2^53−1 |
| FS-8 | DOC | P3 | HYPOTHESIS → подтверждено (CC-07) | предел глубины 256 не описан; схема принимает документы, которые декодер отвергает |
