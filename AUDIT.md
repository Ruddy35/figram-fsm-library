# Аудит Figram: что доказано, что проверено, чему приходится доверять

## Главное

Отсутствие ошибок можно **доказать** только для кода, описанного в Lean.
Для остального его можно только **проверить** — исчерпывающе, но не
математически. Ниже граница проведена точно: каждое утверждение относится
либо к доказанному (теорема Lean, без `sorry`, только стандартные аксиомы
`propext`, `Quot.sound`, `Classical.choice`), либо к проверенному (тест в
`verify.sh` с контролем чувствительности), либо к доверенному (то, что не
проверяется в этом проекте вообще).

## 1. Доказано

### Семантика и компилятор

| Теорема | Точное утверждение |
|---|---|
| `Chart.compile_correct` | Для любой схемы `c` с `c.compile.wf`, любого снимка `s`, события `ev`, значений условий `env`: `c.compile.step s ev env = c.step s ev env` (тот же снимок, те же действия) |
| `Chart.run_correct`, `session_correct` | То же для любой конечной последовательности событий и для сессии с первого входа |
| `Machine.step_state_valid` | Для автомата с `wf` после шага из **любого** снимка текущее сообщение принадлежит `states` |
| `Chart.chart_run_valid` | После любого непустого сценария из любого снимка пользователь на сообщении схемы |
| `Machine.step_guard_local` | Если два набора значений условий совпадают на `requiredGuards`, результаты шага равны |

### Формат документа

| Теорема | Точное утверждение |
|---|---|
| `Format.decode_encode` | Для документа с `DocWF`: `decode (encode d) = .ok d` |
| `Format.encode_injective` | Для документов с `DocWF`: `encode d₁ = encode d₂ → d₁ = d₂` |
| `Format.check_roundtrip` | `d.check = [] → decode (encode d) = .ok d` |
| `Format.decode_requires` | Принятый документ требует только известных расширений |
| `Format.toChart_strip`, `toChart_decls` | Аннотации и тексты описаний не влияют на схему, а значит, на поведение |

### Протокол движка

| Теорема | Точное утверждение |
|---|---|
| `Engine.decSnapshot_encSnapshot` | Для допустимого снимка (`SnapOK`): `decSnapshot (encSnapshot s) = .ok s` |
| `Engine.step_snapOK` | Для автомата с `wf` и `namesOK`, допустимого `s` и непереполненного счётчика результат шага допустим |
| `Engine.reply_readable` | Следствие двух предыдущих: снимок в ответе движка читается движком обратно тем же |
| `Engine.handle_step` | Если запрос `step` разобран, все нужные условия переданы и счётчик не переполнен, ответ — ровно `result id (m.step s ev (envOf gs))` |
| `Engine.guards_irrelevant` | Значения условий вне `requiredGuards` не влияют на шаг |

Условия `wf` и `namesOK` проверяются при загрузке движка (`Engine.load`):
автомат, не прошедший их, не загружается. Поэтому условия теорем
выполняются для любого реально исполняемого автомата.

## 2. Проверено тестами (не доказано)

| Компонент | Почему не доказан | Чем проверен | Контроль чувствительности |

| Разбор запросов и ответов движка вне `step` | Обвязка вокруг доказанных функций | Фиксированные сценарии, 100 случайных документов, 24 граничных снимка против схемы | 107 из 107 мутаций; 4 вида порчи ответов ловятся |

| Python-клиент | Код на Python | 13 видов сбоев движка × 8 потоков (включая процесс, не читающий вход, и ответы неправильной формы); 300 одновременных запросов при переполненном канале; срок вызова от его начала; контракт методов (`step` не возвращает `need`, несериализуемые аргументы, сбор аварийного процесса); пустой stderr | — |
| Тестовая обвязка | Код на Python | Самопроверка: 11 видов порчи ответов, неполные и задвоенные ответы, ноль мутаций, зависший движок с потомками; порча засчитывается, только если инструмент сообщил о нарушении и не упал по посторонней причине | каждый случай → код 1 с распознаванием; настоящий движок → 0 |
| Контракт хоста | Внешняя система | Эталонный хост: 30 пользователей, двойная доставка, ~140 сбоев | Хост без контракта даёт повторные заказы |

## 3. Доверенная база (не проверяется здесь)

* Ядро Lean (проверка доказательств) и стандартные аксиомы.
* Компилятор Lean в C, компилятор C, рантайм Lean (`libleanrt`, `libInit`):
  исполняемый код получается из доказанных определений компилятором,
  который сам не верифицирован.
* Операционная система, cgo и рантайм Go, интерпретатор Python.
* Код условий и действий разработчика и хост.
* Честная параллельность на многоядерной машине: в среде аудита одно ядро;
  проверка — `.github/workflows/verify.yml`.

## 4. Что нашёл и исправил этот аудит

| Находка | Риск | Исправление |
|---|---|---|
| Глубина вложенности JSON ограничена только стеком потока: в процессе движка миллион уровней проходит, но в потоке Go или Python стек меньше, и поведение не гарантировано | Падение встроенного движка на злонамеренном запросе | Явный предел `maxDepth = 256` в парсере; тест в фаззере (глубины 255–300) |
| Протокол движка не был в доказанной зоне: корректность чтения снимка, замкнутость ответов, соответствие ответа шагу | Ошибка кодека снимка незаметна для доказательств ядра | Теоремы `decSnapshot_encSnapshot`, `step_snapOK`, `reply_readable`, `handle_step`; движок при загрузке проверяет `wf` и `namesOK` |
| Сообщение об ошибке разбора в CLI-команде тестирования печаталось сырым и могло содержать перевод строки | Сбивало построчный обмен в тестах | Сообщения экранируются; в протоколе движка они и так экранировались |

Проверено и оказалось безопасным: невалидный UTF-8 из C или Go рантайм
Lean заменяет символом U+FFFD, поэтому инварианты строк не нарушаются.
Неэкранированные данные в ответах движка невозможны: все ответы проходят
`renderCompact`.

## 5. Как воспроизвести

```bash
./verify.sh            # ~160 с: сборка, теоремы, все тесты, сверка bin/ с исходниками
./verify-prebuilt.sh   # ~90 с без Lean: все тесты на собранном движке из bin/
./verify-prebuilt.sh --quick   # ~10 с, сокращённая, явно перечисляет пропущенное
```

Журнал прогона — `VERIFY.log`.
