# Аудит Figram: что доказано, что проверено, чему приходится доверять

## Главное

Отсутствие ошибок можно **доказать** только для кода, описанного в Lean.
Для остального его можно только **проверить** — исчерпывающе, но не
математически. Ниже граница проведена точно: каждое утверждение относится
либо к доказанному (теорема Lean, без `sorry`, только стандартные аксиомы
`propext`, `Quot.sound`, `Classical.choice`), либо к проверенному (тест в
`verify.sh` с контролем чувствительности), либо к доверенному (то, что не
проверяется в этом проекте вообще).

## 1. Доказано

### Семантика и компилятор

| Теорема | Точное утверждение |
|---|---|
| `Chart.compile_correct` | Для любой схемы `c` с `c.compile.wf`, любого снимка `s`, события `ev`, значений условий `env`: `c.compile.step s ev env = c.step s ev env` (тот же снимок, те же действия) |
| `Chart.run_correct`, `session_correct` | То же для любой конечной последовательности событий и для сессии с первого входа |
| `Machine.step_state_valid` | Для автомата с `wf` после шага из **любого** снимка текущее сообщение принадлежит `states` |
| `Chart.chart_run_valid` | После любого непустого сценария из любого снимка пользователь на сообщении схемы |
| `Machine.step_guard_local` | Если два набора значений условий совпадают на `requiredGuards`, результаты шага равны |

### Формат документа

| Теорема | Точное утверждение |
|---|---|
| `Format.decode_encode` | Для документа с `DocWF`: `decode (encode d) = .ok d` |
| `Format.encode_injective` | Для документов с `DocWF`: `encode d₁ = encode d₂ → d₁ = d₂` |
| `Format.check_roundtrip` | `d.check = [] → decode (encode d) = .ok d` |
| `Format.decode_requires` | Принятый документ требует только известных расширений |
| `Format.toChart_strip`, `toChart_decls` | Аннотации и тексты описаний не влияют на схему, а значит, на поведение |

### Протокол движка

| Теорема | Точное утверждение |
|---|---|
| `Engine.decSnapshot_encSnapshot` | Для допустимого снимка (`SnapOK`): `decSnapshot (encSnapshot s) = .ok s` |
| `Engine.step_snapOK` | Для автомата с `wf` и `namesOK`, допустимого `s` и непереполненного счётчика результат шага допустим |
| `Engine.reply_readable` | Следствие двух предыдущих: снимок в ответе движка читается движком обратно тем же — в модели JSON `J`; текст ответа и его разбор не доказаны |
| `Engine.handle_step` | Если запрос `step` уже разобран в модель `J` (`handleObj`; строковый `handle` не доказан), все нужные условия переданы и счётчик не переполнен, ответ — ровно `result id (m.step s ev (envOf gs))` |
| `Engine.guards_irrelevant` | Значения условий вне `requiredGuards` не влияют на шаг |

Условия `wf` и `namesOK` проверяются при загрузке движка (`Engine.load`):
автомат, не прошедший их, не загружается. Поэтому условия теорем на автомат
выполняются для любого реально исполняемого автомата. Условие `SnapOK` на
входной снимок обеспечивает строгий `decSnapshot`; связь `decSnapshot` →
`SnapOK` в основной сборке не доказана. Все теоремы о протоколе относятся к
модели JSON `J`: текст запроса и ответа, CLI и FFI — вне доказанной зоны.
Решение 7 из README (срабатывание таймера только с текущим жетоном) — свойство
разбора запроса `Engine.decEvent`, а не модели ядра: в модели событие
`.named "timer:x"` принимается без жетона, и теоремы этого не исключают.

## 2. Проверено тестами (не доказано)

| Компонент | Почему не доказан | Чем проверен | Контроль чувствительности |
|---|---|---|---|
| Текстовый JSON: разбор и печать (`FormatIO.lean`) | `partial`-функции над символами; доказательство потребовало бы лемм о строках и печати чисел | Дифференциально против `json` Python с ограничениями формата: 30 000 случаев в `verify.sh` (фиксированное зерно), 0 расхождений; значения сравниваются точно, с порядком ключей; напечатанное перечитывает сам Figram | «Парсер» без ограничений формата обнаруживается |
| Разбор запросов и ответов движка вне `step` | Обвязка вокруг доказанных функций | Фиксированные сценарии, 100 случайных документов, 24 граничных снимка против схемы, граничные случаи протокола (`protocol_edges.py`: `restart`, частичные и не-булевы условия, событие таймера без жетона, `hello`) | 107 из 107 мутаций таблиц; мутанты разбора, `restart` и `hello`, которых `Mutate.lean` не порождает, ловит `protocol_edges.py`; 11 видов порчи ответов ловятся (самопроверка обвязки) |

| Go-обёртка | Код на Go | Эталонные сценарии из 600 горутин, 4 загрузки документа, `-race`; строгая проверка протокола каждого ответа и ожиданий сценария; `Close` и 5000 перезагрузок | 7 видов порчи ответов, повреждённая строка → ненулевой код (`null` в ожиданиях — ручная проверка, в `verify.sh` не входит); без `Close` — рост ~50 МБ |
| Python-клиент | Код на Python | 13 видов сбоев движка × 8 потоков (включая процесс, не читающий вход, и ответы неправильной формы); 300 одновременных запросов при переполненном канале; срок вызова от его начала; контракт методов (`step` не возвращает `need`, несериализуемые аргументы, сбор аварийного процесса); пустой stderr | — |
| Тестовая обвязка | Код на Python | Самопроверка: 11 видов порчи ответов, неполные и задвоенные ответы, ноль мутаций, зависший движок с потомками; порча засчитывается, только если инструмент сообщил о нарушении и не упал по посторонней причине | каждый случай → код 1 с распознаванием; настоящий движок → 0 |
| Контракт хоста | Внешняя система | Эталонный хост: 30 пользователей, двойная доставка, ~140 сбоев (откат базы, сброс пользователя, общий ресурс и подделка событий таймера не моделируются — HOST.md, раздел 7) | Хост без контракта даёт повторные заказы; хост без барьера (`--no-barrier`, вручную, в `verify.sh` не входит) — неверные ветки |

**Слепые зоны санитайзеров.** ASan и valgrind не видят ошибок памяти в
объектах Lean: куча Lean — mimalloc, а не malloc, и use-after-free объекта
Lean для них невидим; шаг «ASan и UBSan» в `verify.sh` инструментирует только
`figram_ffi.c` и обвязку. TSan не замечает удалённую пометку `lean_mark_mt`
(независимый аудит: 0 предупреждений при 19 112 неверных ответах), потому что
под TSan `lean.h` делает счётчики ссылок атомарными, а при параллельных
загрузках TSan даёт ложные срабатывания из-за повторного использования памяти
mimalloc. Поэтому «санитайзер чист» доказательством не считается: рабочий
оракул для FFI и многопоточности — функциональный стресс со сверкой каждого
ответа с эталоном (16 потоков × 20 000 вызовов в C, 600 горутин и тест
перезагрузки в Go).

**Эквивалентные мутанты.** `figram-engine --mutants` порождает мутации таблиц
автомата и не проверяет, отличимы ли они от исходного. На документе с
недостижимыми ветками — вариант после варианта без условия, повтор условия в
стрелке, недостижимое сообщение, стрелка `timer:X` на сообщении без таймера X
(после исправления таймеров старой версии она недостижима через протокол) —
часть мутантов эквивалентна: их поведение совпадает с исходным, и «выжившая»
мутация не означает слабость тестов. Сначала проверяйте, достижима ли
испорченная ветка. В `verify.sh` мутации гоняются на примерах без таких веток:
обнаружены все 107.

## 3. Доверенная база (не проверяется здесь)

* Ядро Lean (проверка доказательств) и стандартные аксиомы.
* Компилятор Lean в C, компилятор C, рантайм Lean (`libleanrt`, `libInit`):
  исполняемый код получается из доказанных определений компилятором,
  который сам не верифицирован.
* Операционная система, cgo и рантайм Go, интерпретатор Python.
* Код условий и действий разработчика и хост.
* Честная параллельность на многоядерной машине: у авторов было одно ядро;
  проверка — CI `.github/workflows/verify.yml` на 4 ядрах (10 000 горутин
  под `-race` и 100 000 без, расхождений 0).

## 4. Что нашёл и исправил этот аудит

| Находка | Риск | Исправление |
|---|---|---|
| Глубина вложенности JSON ограничена только стеком потока: в процессе движка миллион уровней проходит, но в потоке Go или Python стек меньше, и поведение не гарантировано | Падение встроенного движка на злонамеренном запросе | Явный предел `maxDepth = 256` в парсере; тест в фаззере (глубины 255–300) |
| Протокол движка не был в доказанной зоне: корректность чтения снимка, замкнутость ответов, соответствие ответа шагу | Ошибка кодека снимка незаметна для доказательств ядра | Теоремы `decSnapshot_encSnapshot`, `step_snapOK`, `reply_readable`, `handle_step`; движок при загрузке проверяет `wf` и `namesOK` |
| Сообщение об ошибке разбора в CLI-команде тестирования печаталось сырым и могло содержать перевод строки | Сбивало построчный обмен в тестах | Сообщения экранируются; в протоколе движка они и так экранировались |

Невалидный UTF-8 из C или Go рантайм Lean молча заменял символом U+FFFD:
инварианты строк не нарушались, но разные байты давали одно имя, а тот же
документ из файла отвергался (находка P-18 независимого аудита). Теперь запрос
с невалидным UTF-8 отвергается с кодом `parse_error` и на процессном пути, и
через FFI (FORMAT.md, раздел 7). Неэкранированные данные в ответах движка
невозможны: все ответы проходят `renderCompact`.

## 5. Как воспроизвести

```bash
./verify.sh            # 3–4 мин: сборка, теоремы, все тесты, сверка bin/ с исходниками
./verify-prebuilt.sh   # 2–3 мин без Lean: все тесты на собранном движке из bin/
./verify-prebuilt.sh --quick   # ~20 с, сокращённая, явно перечисляет пропущенное, код выхода 3
./verify-faults.sh prebuilt     # каждая внедрённая неисправность делает проверку красной
```

Время — замеры на 4 ядрах: `verify.sh` — около 170 с в CI (версия до
усиления шлюза доказательств) и 229 с на общей машине независимого аудита с
собранным кешем Lake; `verify-prebuilt.sh` — 162 с, `--quick` — 15–18 с там же.

`VERIFY.log` в репозитории — журнал прогона, снятый до последних изменений
`verify.sh`, `ffi/go-example`, README и REVIEW (нет строки теста общего словаря
Go, нет коммита и версий инструментов), поэтому сопоставить его с исходниками
нельзя, и свидетельством о текущей версии он не является. При выпуске он будет
заменён журналом CI-прогона на официальном тулчейне (`.github/workflows/verify.yml`
сохраняет полный вывод артефактом). `verify.sh` печатает в начале коммит, хеш
скрипта и версии инструментов, чтобы журнал можно было сопоставить с исходниками.
